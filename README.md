# QRKot — благотворительный фонд поддержки котиков 🐱

Приложение для вымышленного благотворительного фонда QRKot, который собирает
пожертвования на помощь кошачьей популяции: корм, медицинское обслуживание,
организацию приютов и другие задачи.

## Как это работает

Фонд открывает **целевые проекты** — сборы конкретных сумм под конкретную
задачу. Пользователи отправляют **пожертвования** в фонд, а не в конкретный
проект. Приложение само распределяет деньги:

- каждое пожертвование зачисляется в самый «старый» открытый проект,
  который ещё не набрал нужную сумму;
- если пожертвование больше, чем нужно текущему проекту, он закрывается,
  а остаток автоматически переходит в следующий открытый проект
  (и так по цепочке, пока хватает денег и проектов);
- если открытых проектов нет, остаток пожертвования ждёт нового проекта;
- при создании нового проекта все накопленные «свободные» пожертвования
  автоматически вкладываются в него.

Проект закрывается автоматически, как только набирается нужная сумма.

## Запуск проекта

1. Клонируйте репозиторий и перейдите в его корень:

```bash
git clone <адрес-репозитория>
cd cat-charity-2
```

2. Создайте и активируйте виртуальное окружение:

- **Windows (cmd):** `python -m venv venv` затем `venv\Scripts\activate`
- **Windows (PowerShell):** `python -m venv venv` затем `.\venv\Scripts\Activate.ps1`
- **Windows (Git Bash) / Linux / macOS:** `python -m venv venv` затем `source venv/bin/activate`

3. Установите зависимости:

```bash
pip install -r requirements.txt
```

4. Настройте переменные окружения: создайте файл `.env` в корне проекта:

```env
DATABASE_URL=sqlite+aiosqlite:///./db.sqlite3
```

5. Примените миграции:

```bash
alembic revision --autogenerate -m "Initial migration"
alembic upgrade head
```

6. Запустите сервер (обязательно из корня проекта):

```bash
uvicorn app.main:app --reload
```

Документация API доступна по адресам:

- **Swagger UI:** http://127.0.0.1:8000/docs
- **ReDoc:** http://127.0.0.1:8000/redoc

## API

### Целевые проекты (`/charity_project`)

| Метод    | Путь            | Описание                                                                                                                                                          |
| -------- | --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST`   | `/`             | Создать проект. Имя — уникальное, 5–100 символов; описание — от 10 символов; требуемая сумма — целое число > 0. После создания запускается логика инвестирования. |
| `GET`    | `/`             | Получить список всех проектов.                                                                                                                                    |
| `PATCH`  | `/{project_id}` | Редактировать проект. Нельзя менять закрытый проект; нельзя установить full_amount меньше текущего invested_amount.                                               |
| `DELETE` | `/{project_id}` | Удалить проект. Нельзя удалить проект, если в него уже инвестированы средства.                                                                                    |

### Пожертвования (`/donation`)

| Метод  | Путь | Описание                                                                                                                                                                 |
| ------ | ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `POST` | `/`  | Создать пожертвование. Сумма — целое число > 0, комментарий — необязательный. После создания запускается логика инвестирования. В ответе — базовые данные пожертвования. |
| `GET`  | `/`  | Получить список всех пожертвований (с полными данными, включая распределение).                                                                                           |

## Модели данных

### CharityProject (таблица `charityproject`)

- `id` — первичный ключ.
- `name` — уникальное название проекта, строка 5–100 символов.
- `description` — описание, строка не менее 10 символов.
- `full_amount` — требуемая сумма, целое число > 0.
- `invested_amount` — собранная сумма, по умолчанию 0.
- `fully_invested` — флаг закрытия проекта, по умолчанию `False`.
- `create_date` — дата создания, проставляется автоматически.
- `close_date` — дата закрытия, проставляется при достижении `full_amount`.

### Donation (таблица `donation`)

- `id` — первичный ключ.
- `comment` — необязательный комментарий.
- `full_amount` — сумма пожертвования, целое число > 0.
- `invested_amount` — распределённая сумма, по умолчанию 0.
- `fully_invested` — все ли деньги из пожертвования распределены, по умолчанию `False`.
- `create_date` — дата пожертвования, проставляется автоматически.
- `close_date` — дата полного распределения, проставляется, когда `invested_amount == full_amount`.

## Логика инвестирования

Вся логика распределения средств реализована в `app/services/investment.py`. Ключевые правила:

- При создании проекта или пожертвования вызывается единая функция распределения.
- Все изменения (балансы, флаги `fully_invested`, даты `close_date`) происходят в рамках одной транзакции.
- `session.commit()` вызывается один раз — в самом конце эндпоинта, после всех расчётов.
- Распределение идёт по принципу FIFO: сначала самый старый открытый проект.
- Остатки пожертвований могут «ждать» новых проектов; при создании проекта они автоматически инвестируются.

Такой подход гарантирует согласованность данных: проект не может быть создан без корректного распределения, а пожертвование не может считаться полностью распределённым, если это не отражено в БД.
